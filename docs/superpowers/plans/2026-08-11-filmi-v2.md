# Filmi v2, plan d'implémentation

**Contexte critique** : l'application est **en production** sur `filmi.shi-ga.net` avec 18 films réels, des avatars choisis par la famille et une séance en cours. Toute modification de schéma doit passer par une migration versionnée, jamais par une recréation de la base. Sauvegarde du 2026-08-11 09:27 dans `~/Documents/Scripts/shigaepouyen/filmi-backups/`.

**Goal** : huit fonctions demandées après le premier usage réel.

## Décisions prises

| Sujet | Décision |
|---|---|
| Suppression d'un film | **Archivage réversible** (`status = 'archived'`), pas de suppression physique. Préserve l'historique et le palmarès. |
| Qui peut archiver ou modifier | Un profil ne peut agir que sur **sa propre liste** : un parent sur la liste adulte, une fille sur la liste enfant. Contrôle **côté serveur**, pas seulement masquage du bouton. |
| Liste des plateformes des réglages | Celles réellement présentes sur les films de la famille, **regroupées par marque**, avec leur logo. |
| Périmètre d'abonnement | Si aucune plateforme du film n'est dans le périmètre, **simple avertissement**, jamais un blocage. Aucun avertissement si le périmètre n'est pas configuré. |

## Migration de schéma, v2

`movies.trailer_url TEXT` est la seule colonne ajoutée. Le mécanisme de migration manquait, il est créé ici.

- `settings` porte la clé `schema_version`, absente signifie version 1.
- `scripts/migrate.php` applique les migrations manquantes dans l'ordre, une transaction par migration, et refuse de rejouer une migration déjà appliquée.
- `scripts/init_db.php` appelle les migrations à la fin, pour qu'un déploiement les applique automatiquement.
- Chaque migration vérifie l'état avant d'agir : `ALTER TABLE ... ADD COLUMN` échoue si la colonne existe, donc on interroge `PRAGMA table_info` d'abord.

## Changement de forme des données de plateformes

Aujourd'hui `movies.providers` contient une liste de noms : `["Netflix","Netflix Standard with Ads"]`. Impossible de regrouper par marque de façon fiable ni d'afficher un logo.

Nouvelle forme, une liste d'objets : `[{"id":8,"name":"Netflix","logo":"/xxx.jpg"}]`.

**Les deux formes doivent être supportées en lecture**, parce que les 18 films existants ne seront reconvertis qu'au prochain rafraîchissement. `Providers::normalise()` accepte les deux et renvoie toujours la nouvelle.

## Regroupement par marque

Règles établies sur les 30 noms réellement présents en production, dans cet ordre :

1. `trim()` (attention, `"Cine+ OCS Amazon Channel "` a une espace finale).
2. Retirer les suffixes de revente : `" Amazon Channel"`, `" Apple TV Channel"`.
3. Retirer les suffixes d'offre : `" Standard with Ads"`, `" with Ads"`, `" Premium"`.
4. Appliquer les alias : `Disney Plus` vers `Disney+`, `Paramount Plus` vers `Paramount+`, `Netflix Standard` vers `Netflix`, `Apple TV Plus` vers `Apple TV+`.
5. La clé de comparaison est le résultat en minuscules, espaces réduites.

Ce qui reste **volontairement distinct**, car ce sont des offres différentes : `Canal+` et `Canal VOD`, `Amazon Prime Video` et `Amazon Video`, `Apple TV Store` et un éventuel `Apple TV+`.

## Bande-annonce

`TmdbService::details()` demande aussi `videos`. Sélection, par ordre de préférence : type `Trailer`, site `YouTube`, `official = true`, langue `fr` ; puis `official` toutes langues ; puis n'importe quel `Trailer` YouTube. Résultat stocké en URL complète `https://www.youtube.com/watch?v=KEY`, ou `null`.

## Tâches

### Tâche 1 : migration, plateformes, bande-annonce, archivage et modification

Toute la logique et ses tests. Aucune vue.

Points d'attention :
- `Providers::normalise()` doit être testé sur les 30 noms réels listés ci-dessus, pas sur des exemples inventés.
- `archive()` et `updateClassification()` ne portent **aucun contrôle d'accès** : ce sont les pages qui vérifient le camp. Le dépôt refuse en revanche une classification incohérente, à savoir un `bet_type` sur la liste enfant, ou son absence sur la liste adulte.
- La migration doit être testée deux fois de suite sur la même base pour prouver son idempotence, et sur une base déjà en version 1 avec des données, pour prouver qu'elle ne perd rien.

### Tâche 2 : les écrans

Fiche détaillée, synopsis, avertissements, réglages des abonnements, conservation des champs.

Points d'attention :
- Le contrôle d'accès sur l'archivage et la modification se fait **côté serveur** dans `public/movie.php`, en comparant `$profile['side']` au `pool` du film. Masquer le bouton ne suffit pas.
- L'avertissement de périmètre ne s'affiche pas si aucun abonnement n'est configuré, sinon tous les films seraient signalés.
- Le lien de bande-annonce s'ouvre dans un nouvel onglet, avec `rel="noopener"`.

### Tâche 3 : migration de la production

Faite par le contrôleur, pas par un agent, parce qu'elle touche les vraies données :
1. Sauvegarde fraîche.
2. Déploiement du code.
3. `scripts/migrate.php` sur le serveur.
4. Rafraîchissement des 18 films pour peupler `trailer_url` et convertir la forme des plateformes.
